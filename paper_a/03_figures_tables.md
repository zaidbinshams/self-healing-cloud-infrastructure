# 03 — Figures and Tables

> Every figure is generated by `python -m eval.plots` (vector PDF in `latex/figures/`, PNG previews in `figures/paperA/` in the repo); data behind each is in `figure_data/`. Colours follow the policy in every figure (blue = PER-SAC warm, orange = runbook, green = cold, yellow = HPA, pink = Kubernetes). Captions are yours: below are the **facts a caption must carry**, not caption text.

## Fig. 1 — Architecture and control loop (TikZ, in `main.tex`)
- **Shows:** Machine A (K3s: Online Boutique, Chaos Mesh, Prometheus, Kubernetes API) and Machine B (Locust, env, agent, executor/injector) over a wireless link; data paths (HTTP load, PromQL, request logs) and control paths (patch/scale, faults).
- **Caption facts:** one tick every 20 s; telemetry collected concurrently within 3 s; one action in flight (global lock); the agent's credential is limited to the 4 managed deployments in one namespace; B is the clock authority.
- If you redraw it in a drawing tool, keep the two-machine split and the link labels.

## Table I — Faults (in `main.tex`)
- Severities, targets, cure conditions and curing actions from the contract. The curing-action column is the pre-registered outcome grid (documentation only; the agent never sees it).

## Table III — Main evaluation (in `main.tex`; data `summary_main.csv`)
- 5 policies × (recovered per fault, censored median MTTR per fault, pooled, mean SLA penalty, actions per fault episode, NULL with action).
- **How to read:** censored medians make a policy that misses half the episodes look like 240–360 s; the bracketed "recovered only" medians show speed when it does recover. Say both.
- **What to say:** Kubernetes cures nothing (no controller reacts to these faults); HPA only F4; the warm agent matches the runbook's coverage except F2-curr and is a tick faster on F1/F4.

## Fig. 2 — Pooled Kaplan–Meier (`a1_km.pdf`; data `km_curves.csv`)
- **Shows:** P(not yet recovered) vs time since injection, F1–F4 pooled (40 episodes per policy), censoring at 360 s.
- **How to read:** a lower curve is better; the plateau height = fraction never recovered (PER-SAC 0.125 = 5/40; runbook 0.05 = 2/40; HPA 0.75; cold 0.625; Kubernetes 1.0).
- **Caption facts:** log-rank vs PER-SAC: Kubernetes p = 9.2×10⁻¹⁷, HPA 2.3×10⁻⁷, cold 3.3×10⁻⁶, runbook 0.95.
- **Say:** PER-SAC drops earlier (more 40–60 s recoveries) but plateaus higher than the runbook (F2-curr).

## Fig. 3 — MTTR per fault and policy (`a2_mttr_by_fault.pdf`, full width; data `episodes_main.csv`)
- **Shows:** one dot per episode, black bar = median, dotted line = 360 s censoring.
- **Say:** F1: agent 40–100 s vs runbook 80 s; F2: split between cart (cured) and curr (censored); F3: both ~40–80 s; F4: HPA's 40 s episodes, the agent 60–80 s, the runbook 60–80 s.

## Table IV — Actions per fault (in `main.tex`; data `actions_main.csv`, `actions_seed1.csv`, `actions_edge.csv`)
- Executed action sequences per fault/target and policy.
- **Say:** the learned policy reproduces the runbook's curing action per fault class without seeing fault identity; it never acts on F2-curr; it never acts in NULL episodes. The cold agent (not in the table; one sentence) repeats RESTORE cartservice ~10–24 times per episode (`actions_main.csv`).

## Fig. 4 — Training return (`a3_training.pdf`; data `training.csv`)
- **Shows:** 10-episode rolling mean return; warm seed 0 (solid blue), warm seed 1 (dotted blue), cold (green, 100 episodes).
- **Caption facts:** return ∈ [−1.09, 0] per tick, summed per episode; the cold run is 100 episodes (Amendment 7).
- **Say:** the warm runs start near −2 and stay there (refinement, not exploration); the cold run is at −5 to −15 for its whole 100 episodes. H3 test over episodes 1–100 [N18].

## Fig. 5 — Edge vs main (`a4_edge.pdf`; data `summary_edge.csv`, `summary_main.csv`)
- **Shows:** per-fault median MTTR, hollow = main evaluation (n = 10 per fault), filled = netem edge subset (n = 4 per fault), runbook (orange, left) and PER-SAC (blue, right).
- **Caption facts:** netem +150 ms delay and 1 % loss on Kubernetes API and Prometheus traffic only; the edge subset = the first 4 schedule entries per fault type.
- **Say:** both policies keep their per-fault behaviour; F1 PER-SAC 59 → 99 s and runbook F2 89 → 178 s are 4-episode medians; H5 not established at n = 16.

## Fig. 6 (optional) — Seed 1 (`a5_seed1.pdf`; data `summary_seed1.csv`, `summary_main.csv`)
- **Shows:** per-fault median MTTR, hollow = main block (PER-SAC seed 0, runbook), filled = seed-1 block (PER-SAC seed 1, runbook anchor).
- **Say:** the runbook anchor moves by at most one tick (20 s) per fault (F2 89 → 99, F3 50 → 60, F4 80 → 60 s), and pooled it does not move (p = 0.70), so there is no drift between days. Seed 1 vs seed 0: F1 90 vs 59 s, F4 79 vs 60 s, F3 60 vs 60 s, F2 230 vs 240 s.
- Drop this figure first if the paper is over 7 pages (Table V carries the replication).

## Regenerating the CSVs from raw data (project lead only; needs `data/` from the backup)
```
python -m eval.analyze --main data/eval/eval_v1_main --edge data/eval/eval_v1_edge \
    --train sac_per=data/m4/sac_per_s0 --train sac_per_cold=data/m4/sac_per_cold_s0 \
    --seed1 sac_per_s1=data/eval/eval_v1_seed1=data/m4/sac_per_s1 --out data/eval/analysis.json
python -m eval.plots --analysis data/eval/analysis.json --main data/eval/eval_v1_main \
    --train sac_per=data/m4/sac_per_s0 --train sac_per_cold=data/m4/sac_per_cold_s0 \
    --train sac_per_s1=data/m4/sac_per_s1 --out figures/paperA
python -m eval.papera_export --analysis data/eval/analysis.json --out paper_a/figure_data
```
